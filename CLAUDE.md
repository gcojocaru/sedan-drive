# CLAUDE.md

Context for working on this repo. See README.md for what the pages do and how to run them.

**Every PR follows the rules and target layout in ARCHITECTURE.md** (imported below). If a change can't follow them, say why in the PR.

@ARCHITECTURE.md

## Stack

- Plain HTML + native ES modules. No bundler, no npm dependencies, no TypeScript.
- three.js **0.184.0** via the import map in each page's `<head>`, served from `vendor/three-0.184.0/` (unmodified copies of the npm files) with SRI `integrity` hashes. To bump it, copy the new files into a new `vendor/three-<version>/`, then update every path *and* every hash in all three pages together, or the browser will refuse to load it. Nothing loads from a CDN at runtime.
- Leaflet 1.9.4 (real-map page only) from `vendor/leaflet-1.9.4/`, loaded as a classic script → global `L`.
- Serve with `npm run dev` (port 5173). `file://` won't work because of module imports.

## Architecture

- **One car model:** `sedan-model.js` → `buildCar()` (plus the axle constants `FA`, `RA`), imported by all three pages (`drive-map.js`, `drive-track.js`, `sedan-viewer.js`). Page setup around it (studio environment, contact shadows, light controls, driving) lives in the page's own module.
- Units are metres; the car's long axis is +X (front axle at x≈1.32, rear at x≈-1.31), y up.
- Meshes and groups are named (`car.getObjectByName('underbody')`, `steering_wheel`, `front_seat_L`, …). Other code looks parts up by name, so keep names stable when renaming things.
- `road-layout.js` computes directional lanes, junction geometry and spawn/reset positions. `building-fronts.js` lays out facades: the style per building (`facadeStyle`: house, panel block, classic, office, glass, industrial, brick, blank), storeys (`floorGrid`), whole window bays per straight run of wall (`bayCoords`), mapped and inferred doors and retail display windows, draws the wall atlas (`wallAtlas`) and shopfront atlas on a supplied canvas context, and holds the photo surface table (`SURFACES`) and `levelPhoto`. Both modules are importable by the Node tests.
- `minimap.js` draws the real-map HUD from projected world geometry. It rasterizes the area once, then samples a north-up view around the car using its world position and heading, with traffic cars as dots (`minimapPoint`).
- `osm-query.js` holds the Overpass query (`overpassQuery`), the cache key (`areaKey`, `CACHE_V`), the ~55 m start-point grid (`snap`), the server list and `AREA_PROXY`. It is imported by both `drive-map.js` and `proxy/worker.js` (Cloudflare Worker, bundled by wrangler), so the proxy only ever runs the game's own query. Change the query there, bump `CACHE_V`, and redeploy the Worker with the site.
- `vector-fallback.js` decodes Mapbox Vector Tiles itself (no library) and maps OpenMapTiles layers to OSM-style tags (`tagsFor`), emitting Overpass-shaped `elements` (ways, and relations for polygons with holes) so `startGame()` doesn't care about the source. Polygons are clipped to their tile so neighbouring tiles' pieces don't overlap; street names come from the `transportation_name` layer by nearest-line match.
- Real-map page modules: `drive-map.js` (map picker: Leaflet + Nominatim, searches cached, max 1 request/s, one reverse lookup on Drive → `startGame()`: loading screen, renderer, `createSky()`, `buildWorld()`, car, time of day and weather, game loop, HUD) → `sky.js` (sun, sky, lights, rain and snow) → `map-data.js` (`loadArea`: IndexedDB cache, then `fetchArea`: proxy, then Overpass servers one at a time; 429/406 rests a server for 30 s; a 503 from the proxy means it already tried them all; if nothing delivers, `vector-fallback.js` builds the place from OpenFreeMap vector tiles, which isn't cached) → `world.js` (road/area tag tables: `areaKind`, `ROAD` widths, `PATH`; `buildWorld()` and its per-feature builders) → `buildings.js` (`buildBuildings()`: roof shapes, wall/roof materials, building parts, shopfronts, `inBuilding`) → `world-kit.js` (`fillPoly`, `makeTex`, `tagColor`, …) → `geom.js` (pure: `ribbon`, `obb`, `clipHalf`, `tri3`/`wallStrip`, `seaPolys()` coastline → sea, …). `drive-core.js` has the driving shared with the test track.
- World build order inside `buildWorld()`, one function each: `parseElements` → `groundLayers` → area fills → `layRoads` (sea, roads, lane marks, stop lines) → `roadLookup` (`roadAt`) → `paintCrossings`, `layRailways` → flat layer meshes → `buildWalls` → `areaLookup` (`areaAt`) → `buildBuildings` → `plantTrees` → `streetLamps`. Keep this order: later builders use earlier lookups (`roadAt`, `areaAt`, `inBuilding`), and the ground layers' buffers must be filled before the flat layer meshes are made. `startGame()` then adds the car and calls `applyTime()`.
- Lighting (real-map page, `sky.js`): `createSky(renderer, scene, lat)` returns `TIMES`, time-of-day presets in local *solar* time, and `sunAt(h)`, the real sun direction for the place's latitude and today's date. `set(h, forceNight, weather)` sets everything from the sun elevation and the weather's `LOOK` (cloud cover, haze, gloom): directional light (sun / soft dusk sky light / moon) and how hard its shadows are, hemisphere + environment fill, fog, exposure, rain or snow, and redraws the sky canvas (`drawSky`, equirect, sun drawn where the light comes from, clouds, overcast deck) plus its PMREM. `update(dt, cameraPosition)` moves the rain streaks / snowflakes (world-space drops folded into a 40 m box around the camera, none within 1.5 m of it so the cabin stays dry) and flashes lightning in a thunderstorm. `applyTime()` in `drive-map.js` calls `set()` and adds lit windows, street lamps, auto headlights (on when it gets dark or murky, once) and the HUD label.
- Time and weather (real-map page): `tSel` / `wSel` are `'live'` or an index into `TIMES` / `WEATHERS` (T / E cycle live → presets, N toggles night; the two `<select>`s in the settings dialog `#settings` (which also has the traffic level), opened with Esc or the touch Settings button, do the same, and driving pauses while it or the edge dialog is open). Live time is the place's solar time now (`solarHour`); live weather is `weatherNow()` from Open-Meteo (free, no key, CORS; CC BY 4.0, so the "Weather data by Open-Meteo.com" link shows while it is used), asked while the map loads and again every 15 min; the sun is re-set every 5 min. The clock shows local civil time from Open-Meteo's `utc_offset_seconds` (a longitude guess without it), presets too. Both choices travel to the next area in the history entry (`time`, `weather`). Tested in `test/weather.test.js`. The single shadow map covers a box centred 45 m ahead of the car (`placeShadow(x, z)`), snapped to texels so edges don't shimmer. Flat ground layers are separate meshes stacked a few mm apart (`LAYERS`, lowest first); the base ground plane sits 3 cm below them.
- Buildings (`buildings.js`): walls and roofs are generated per footprint (no `ExtrudeGeometry`). Pitched roofs are the lower envelope of planes over the footprint's minimum-area box (`roofPlanes`); walls rise to that roof line, and the roof faces cover the footprint grown by 0.45 m (`offsetRing`) so eaves and verges overhang, with a dark underside only where they overhang (drawn everywhere, the hidden underside costs fill: the log depth buffer turns off early-z). Footprints that aren't box-like enough fall back to flat roofs, which sit inside a parapet with a coping. All walls share one material (`facadeMaterial`): wall uv is (window bays, storeys) and the `facade` attribute is [style, storey above the top one]; its shader draws the style's cell of the wall atlas (ground floor or upper) per bay and storey, keeps glass and trim out of the building colour, and at night lights a random share of windows per style through `emissiveIntensity`. The atlas is one texture: colour in RGB, and alpha 1 for wall, ½ for trim, 0 for glass. Wall areas also take a photo surface (plaster, brick, concrete or corrugated metal, `FACADES[i][4]`) from a texture array, laid in metres along the wall (the per-style tables are read in the vertex shader). Roofs are three meshes with photo textures in metres: flat (tarred gravel), tiled (clay tiles) and metal (corrugated). The photos are CC0 from Poly Haven, in `textures/` (credited in its README, copied by `npm run build`), loaded once each and levelled to a neutral grey (`levelPhoto`) so building and roof colours still come from the tags and palettes; until they arrive the surfaces are plain grey.
- The playable area is a 1 km square (`HALF = 500` m) around the chosen point.
- `radio.js` is the car radio for both drive pages (`Q` / `Shift+Q`). `radio(show, find, tuningStatic)` → `tune(step)` plays through one `<audio>`; `radioHud()` is the GTA-style station name both pages pass as `show` (it makes its own element, no page CSS); `find()` gives `[name, url]` pairs and runs on the first tune (again after finding nothing). The real-map page passes `stationsNear(lat0, lon0, fetch)`: radio-browser.info (free, no key, CORS `*`, `all.api` = round-robin over its mirrors), the most-clicked stations within 200 km plus that country's top ones (country = nearest geo-tagged station, since few stations have coordinates), max 30. Only `https://` and non-HLS streams: the site is HTTPS, and `<audio>` can't play HLS. The test track uses the Romanian `STATIONS` presets. Nothing is cached or stored. Tested in `test/radio.test.js` (`npm test`).
- `touch.js` is the on-screen driving controls for both drive pages. `touchControls(extras)` (called from each page's `begin()`) keeps only steer ◀ ▶, Gas and Brake/Reverse on screen (held); the ••• toggle opens a panel with Handbrake (held) and the page's `[label, code]` extras (Lights, Camera, Radio…, tapped). Every button just dispatches the `KeyboardEvent` its key would (`ArrowLeft`, `ArrowUp`, `Space`, `KeyH`, …) on `window`, so the pages' own key handlers drive the car and there is no separate touch path. Hold buttons capture their pointer so a finger sliding off doesn't let go. The controls show when the primary pointer is coarse or after any touch, and hide on a real (trusted) key press. It makes its own elements and `<style>`; while the controls are shown `<html>` has the class `touch-ui`, which the real-map page uses to move its minimap to the top left and its street name clear of the buttons.
- `three-d-stage.js` is a generic viewer web component (from the Claude Design starter, now owned here): renderer, studio lights, orbit, GLB/OBJ export.

- `area-travel.js` projects the crossing into a neighboring area, manages the boundary prompt and throttles travel attempts. The history entry carries the arrival pose, previous area for failed loads and cooldown fallback through a reload.
- `driving-audio.js` synthesizes engine and tuner sounds on both driving pages. Audio starts on a user gesture.
- Traffic (real-map page): `traffic.js` (pure, Node-tested) → `laneGraph(roads, junctions, HALF)` splits the prepared roads (`road-layout.js`; `nodeKey` says which vertices are shared) where they meet into edges, one per direction, with a lane piece per lane cut back clear of each junction (by the meeting roads' widths and angle); `createTraffic(graph, { rand, max, seen })` → `{ cars, step(dt, player), hit(x, z), clear(x, z, r), setLevel(level, x, z) }`. Each car plans its route about 120 m ahead (lane pieces joined by Bézier turns, rarely into dead ends), slows for bends, keeps its gap to whatever body is in its path (other cars, the player), and claims each junction before entering: no car in it may have a turn whose swept body touches its own (`compatible`), first come first served (a waiting car that can't go yet keeps its place from 4 to 20 s, so streams can't starve a side road and no circle of waiting cars lasts; a car held up by this one never blocks it), and there must be room beyond (no blocking the box). Junctions too close together to wait between are claimed together; a waiting car stops far enough back (`waitBack`) that no other turn or exit passes its body. Traffic lights: `laneGraph(…, signals)` takes the mapped `highway=traffic_signals` points (`buildWorld()` returns them as `signalPts`); a junction node with one within 30 m is controlled, and nodes joined by a short edge share a controller. With none mapped anywhere in the data (as on the vector fallback), lights go where two main roads (`MAIN`) cross at a four-way junction that isn't a roundabout. Every road into a controller gets a light in one of two phases by direction (the widest road's axis first) and a signal head at its kerb (`graph.signals`: `{ e, x, z, h, state }`); `lightAt(signal, t)` cycles 18 s green, 3 s amber, 2 s all red per phase. Cars stop at red, and at amber when they can do so comfortably, without queueing for the junction meanwhile (a red light doesn't count towards being stuck). `traffic-lights.js` draws the poles and heads (instanced) and the lamp that's on, glowing at night. Cars live within 260 m of the player; `LEVELS` (Off/Light/Normal/Heavy) set the density. `seen(x, z)` (the camera frustum) keeps new cars from appearing on screen and lets cars stuck in a jam or at a dead end go once they're out of sight. `traffic-cars.js` draws them: one extruded body, glass, trim and lamps as `InstancedMesh`es, paint per car, brake lights, head and tail glows at night. `drive-map.js` steps it every frame (also before Start, not while paused; that also sets the lights), counts traffic cars as obstacles in `blocked()`, and clears cars from the spot you reset to. Tested in `test/traffic.test.js`.

## Browser storage keys

- `sedan-area-cooldown-v1` (localStorage) — earliest time for another adjacent-area load, in epoch milliseconds.
- `sedan-driving-muted-v1` (sessionStorage) — whether engine and tuning sounds are muted in this tab.

- `sedan-map-last-place-v1` — last chosen place (real-map page)
- `sedan-drive-best-v1` — best lap time (Drive.html)
- `sedan-lights-v1` — viewer light toggles (Sedan.html)
- `sedan-map-car-v1` — chosen car on the real-map page (`sedan` or `vaz`)
- `sedan-map-traffic-v1` — traffic level on the real-map page, an index into `LEVELS` in `traffic.js` (0 off … 3 heavy; normal when unset)
- IndexedDB `sedan-map-cache` / store `osm` — cached Overpass responses, keyed `areaKey()` = `osm6:<lat>,<lon>:<HALF>` (4 decimals, snapped). Bump `CACHE_V` in `osm-query.js` whenever the query changes; entries with an older prefix are pruned after the next download.
- `sedan-geocode-cache-v1` — Nominatim results (last 60 searches / reverse lookups)
- `sedan-overpass-rest-v1` — Overpass servers to leave alone until a time (after HTTP 429/406)

## Conventions

- Code is written densely (many statements per line, short helper names like `V`, `B`, `add`). Match the surrounding style rather than reformatting whole files.
- Add any new library as an exact version under `vendor/<name>-<version>/` with its licence, not from a CDN. New textures go in `textures/`, CC0 only, with a row in `textures/README.md` (a test checks every `SURFACES` file is there and credited).
- `reference/` (git-ignored, local only) holds the photos the model was matched against (Logan front 3/4, front, interior, wheel, underbody) — look at them when working on the car's shape if they're present. They are third-party photos: never commit them; the repo is public.
