# CLAUDE.md

Context for working on this repo. See README.md for what the pages do and how to run them.

**Every PR follows the rules and target layout in ARCHITECTURE.md** (imported below). If a change can't follow them, say why in the PR.

@ARCHITECTURE.md

The public game version lives in `package.json`. All three game pages use `app-version.js` to display it.

**Every PR bumps the version and adds a changelog entry:** `npm version minor --no-git-tag-version` for features (`patch` for fixes only), and a dated section at the top of `CHANGELOG.md` saying what changed for players, in plain words. A PR stacked on another takes the next version after it.

## Stack

- Plain HTML + native ES modules. No bundler, no npm dependencies, no TypeScript.
- three.js **0.184.0** via the import map in each page's `<head>`, served from `vendor/three-0.184.0/` (unmodified copies of the npm files) with SRI `integrity` hashes. To bump it, copy the new files into a new `vendor/three-<version>/`, then update every path *and* every hash in all three pages together, or the browser will refuse to load it. Nothing loads from a CDN at runtime.
- Leaflet 1.9.4 (real-map page only) from `vendor/leaflet-1.9.4/`, loaded as a classic script → global `L`.
- Serve with `npm run dev` (port 5173). `file://` won't work because of module imports.

## Architecture

- **One car model:** `sedan-model.js` → `buildCar()` (plus the axle constants `FA`, `RA`), imported by all three pages (`drive-map.js`, `drive-track.js`, `sedan-viewer.js`). Page setup around it (studio environment, contact shadows, light controls, driving) lives in the page's own module.
- Units are metres; the car's long axis is +X (front axle at x≈1.32, rear at x≈-1.31), y up.
- Meshes and groups are named (`car.getObjectByName('underbody')`, `steering_wheel`, `front_seat_L`, …). Other code looks parts up by name, so keep names stable when renaming things.
- `street-furniture.js` lays out static cars inside mapped parking outlines and indexes their footprints alongside mapped benches, bollards and bus stops. `furniture-mesh.js` draws these objects and reuses the traffic car meshes.
- `sign-layout.js` places named street and landmark signs using mapped roads, nearby features and ground clearance. `sign-mesh.js` builds their shared texture atlas and meshes.
- `road-layout.js` computes directional lanes, junction geometry and spawn/reset positions, and reads the country the map data lies in (`countryCode`, from the `ISO3166-1` area the Overpass query asks for; none on the vector fallback). `building-fronts.js` lays out facades: the style per building (`facadeStyle`: house, panel block, classic, office, glass, industrial, brick, blank; `mansard` is the zinc slope of a mansard roof), chosen by tags, then type, then height and the region's mix (`REGIONS`, `regionOf(country)`: French, British, Mediterranean and North American looks for untagged buildings, with their wall and roof colours; anywhere else keeps the generic mix, panel blocks first), whether a block gets a mansard (`mansardRoof`), storeys (`floorGrid`), whole window bays per straight run of wall (`bayCoords`), mapped and inferred doors and retail display windows, draws the wall atlas (`wallAtlas`) and shopfront atlas on a supplied canvas context, and holds the photo surface table (`SURFACES`) and `levelPhoto`. Both modules are importable by the Node tests.
- `minimap.js` draws the real-map HUD from projected world geometry. It rasterizes the area once, then samples a north-up view around the car using its world position and heading, with traffic cars as dots (`minimapPoint`).
- `osm-query.js` holds the Overpass query (`overpassQuery`), the cache key (`areaKey`, `CACHE_V`), the ~55 m start-point grid (`snap`), the server list and `AREA_PROXY`. It is imported by both `drive-map.js` and `proxy/worker.js` (Cloudflare Worker, bundled by wrangler), so the proxy only ever runs the game's own query. Change the query there, bump `CACHE_V`, and redeploy the Worker with the site.
- `vector-fallback.js` decodes Mapbox Vector Tiles itself (no library) and maps OpenMapTiles layers to OSM-style tags (`tagsFor`), emitting Overpass-shaped `elements` (ways, and relations for polygons with holes) so `startGame()` doesn't care about the source. Polygons are clipped to their tile so neighbouring tiles' pieces don't overlap; street names come from the `transportation_name` layer by nearest-line match.
- Real-map page modules: `drive-map.js` (map picker: Leaflet + Nominatim, searches cached, max 1 request/s, one reverse lookup on Drive → `startGame()`: loading screen, renderer, `createSky()`, `buildWorld()`, car, time of day and weather, game loop, HUD) → `sky.js` (sun, sky, lights, rain and snow) → `map-data.js` (`loadArea`: IndexedDB cache, then `fetchArea`: proxy, then Overpass servers one at a time; 429/406 rests a server for 30 s; a 503 from the proxy means it already tried them all; if nothing delivers, `vector-fallback.js` builds the place from OpenFreeMap vector tiles, which isn't cached) → `world.js` (road/area tag tables: `areaKind`, `ROAD` widths, `PATH`; `buildWorld(elements, lat0, lon0, scene, say, terrain, { lampLights })` and its per-feature builders) → `buildings.js` (`buildBuildings()`: roof shapes, wall/roof materials, building parts, shopfronts, `inBuilding`) → `world-kit.js` (`fillPoly`, `makeTex`, `tagColor`, `weatherLook`, …) → `geom.js` (pure: `ribbon`, `obb`, `clipHalf`, `tri3`/`wallStrip`, `seaPolys()` coastline → sea, …). `drive-core.js` has the driving shared with the test track; its `step()` takes the ground as `{ vmax, drag, rough, grip, height? }`: `grip` (1 dry, default) scales the brakes and handbrake, caps the engine at 10·grip m/s² and lets the tyres hold the path to 8·grip/(1−grip) m/s² sideways; past that the car slides (`st.slip`, the angle from heading to travel, at most 0.5 rad), scrubbing speed. Dry is unchanged, so the test track drives as before.
- Real elevation comes from Mapzen Terrarium tiles in `terrain.js`. The browser HTTP cache reuses tiles across drives. Heights in metres are relative to the selected centre. Roads and ground share the triangle grid in `terrain-surface.js`. The world returns `driveHeight(x,z)` for vehicles, pedestrians, traffic lights, delivery markers and cameras. It includes the deck and graded approaches from `bridge-decks.js`. Building foundations and verges use the approach height on land, and `bridge-mesh.js` adds the visible structure under the crossing. A failed or timed-out terrain request returns a flat surface.
- World build order inside `buildWorld()`, one function each: `parseElements` → `groundLayers` → area fills → `layRoads` (sea, roads, lane marks, stop lines) → `roadLookup` (`roadAt`) → `paintCrossings`, `layRailways` → flat layer meshes → `buildWalls` → `areaLookup` (`areaAt`) → `buildBuildings` → `plantTrees` → `streetLamps`. Keep this order: later builders use earlier lookups (`roadAt`, `areaAt`, `inBuilding`), and the ground layers' buffers must be filled before the flat layer meshes are made. `startGame()` then adds the car and calls `applyTime()`.
- Lighting (real-map page, `sky.js`): `createSky(renderer, scene, lat, { shadow, drops }, now, height)` returns `TIMES`, time-of-day presets in local *solar* time, and `sunAt(h)`, the real sun direction for the place's latitude and today's date. `set(h, forceNight, weather, snow)` sets everything from the sun elevation and the weather's `LOOK` (cloud cover, haze, gloom): directional light (sun / soft dusk sky light / moon) and how hard its shadows are (below about 20° the fill comes cool from the zenith and the sun turns warmer and stronger; under cloud shadows soften, `shadow.radius` 1 + 5·cover², but stay, `shadow.intensity` 1 − 0.3·cover²; the shadow box is fitted to the ground at low sun and snapped per axis), hemisphere + environment fill, fog, exposure, rain or snow, and redraws the sky canvas (`drawSky`, equirect, sun drawn where the light comes from, clouds, overcast deck) plus its PMREM. `update(dt, cameraPosition)` moves the rain streaks / snowflakes (world-space drops folded into a 40 m box around the camera, none within 1.5 m of it so the cabin stays dry) and flashes lightning in a thunderstorm. `applyTime()` in `drive-map.js` calls `set()` and adds lit windows, street lamps, auto headlights (on when it gets dark or murky, once) and the HUD label.
- Time and weather (real-map page): `tSel` / `wSel` are `'live'` or an index into `TIMES` / `WEATHERS` (T / E cycle live → presets, N toggles night; the two `<select>`s in the settings dialog `#settings` (which also has the traffic level), opened with Esc or the touch Settings button, do the same, and driving pauses while it or the edge dialog is open). Live time is the place's solar time now (`solarHour`); live weather is `weatherNow()` from Open-Meteo (free, no key, CORS; CC BY 4.0, so the "Weather data by Open-Meteo.com" link shows while it is used), asked while the map loads and again every 15 min; the sun is re-set every 5 min. The clock shows local civil time from Open-Meteo's `utc_offset_seconds` (a longitude guess without it), presets too. Both choices travel to the next area in the history entry (`time`, `weather`). `weatherNow()` also reads `snow_depth` and adds up the last 3–4 hours of `precipitation` (`snowDepth`, `recent`); `groundOf(w)` turns a live or preset weather into `{ wet, snow, grip }` (snow from the depth when known, else from falling snow; wet from rain now or recently, not when it froze, and half the snow cover as slush). `applyTime()` passes snow to `sky.set()` (brighter bounce light), `wet`/`snow` to `setGround()` and `grip` to the physics. Tested in `test/weather.test.js`.
- Wet and snowy surfaces: `weatherLook()` in `world-kit.js` → `wear(material, kind)` patches a `MeshStandardMaterial` (`onBeforeCompile`, identical code for every kind so programs are shared; the kind's row of `WEAR` goes in as a uniform). `buildWorld()` wears the flat layers and ground plane (`WORN`: roads/parking `road`, markings `mark`, sidewalks and paving `pave`, the rest `ground`, not water or rails), wall tops, tree crowns and, through `buildBuildings(…, wear)`, roofs, parapets and awnings (`roof`, snow only where the normal faces up). Wet darkens and lowers roughness (puddles from a world-space noise on roads); snow drifts come from one world-space noise so stacked layers agree; roads get patchy grey slush. Street lamps aren't lights, so `streetLamps()` hands their heads to the look (`lamps`, `lit`) and `reflectLamps(x, z)` (from `updateCam`) puts the eight nearest the camera into the road shader, which adds a Blinn glint per lamp (stretched towards the eye at grazing angles, like a real reflection). The single shadow map covers a box centred 45 m ahead of the car (`placeShadow(x, z)`), snapped to texels so edges don't shimmer. Flat ground layers are separate meshes stacked a few mm apart (`LAYERS`, lowest first); the base ground plane sits 3 cm below them.
- Buildings (`buildings.js`): walls and roofs are generated per footprint (no `ExtrudeGeometry`). Pitched roofs are the lower envelope of planes over the footprint's minimum-area box (`roofPlanes`); walls rise to that roof line, and the roof faces cover the footprint grown by 0.45 m (`offsetRing`) so eaves and verges overhang, with a dark underside only where they overhang (drawn everywhere, the hidden underside costs fill: the log depth buffer turns off early-z). Footprints that aren't box-like enough fall back to flat roofs, which sit inside a parapet with a coping. Mansards (`roof:shape=mansard`, or by default on terraced 4- to 9-storey blocks where the region builds them, France) follow any footprint: a stone cornice, then a one-storey zinc slope leaning in by up to 0.35 of its height (`offsetRing` with one distance per edge, less where the slopes would fold over) with a dormer drawn per window bay, and a flat top. Party walls, footprint edges another building shares (the same two nodes), get no windows, and mansards rise straight up from them. All walls share one material (`facadeMaterial`): wall uv is (window bays, storeys) and the `facade` attribute is [style, storey above the top one]; its shader draws the style's cell of the wall atlas (ground floor or upper) per bay and storey, keeps glass and trim out of the building colour, and at night lights a random share of windows per style through `emissiveIntensity`. The atlas is one texture: colour in RGB, and alpha 1 for wall, ½ for trim, 0 for glass. Wall areas also take a photo surface (plaster, brick, concrete or corrugated metal, `FACADES[i][4]`) from a texture array, laid in metres along the wall (the per-style tables are read in the vertex shader). Roofs are three meshes with photo textures in metres: flat (tarred gravel), tiled (clay tiles) and metal (corrugated). The photos are CC0 from Poly Haven, in `textures/` (credited in its README, copied by `npm run build`), loaded once each and levelled to a neutral grey (`levelPhoto`) so building and roof colours still come from the tags and palettes; until they arrive the surfaces are plain grey.
- The playable area is a 1 km square (`HALF = 500` m) around the chosen point.
- `radio.js` is the car radio for both drive pages (`Q` / `Shift+Q`). `radio(show, find, tuningStatic)` → `tune(step)` plays through one `<audio>`; `radioHud()` is the GTA-style station name both pages pass as `show` (it makes its own element, no page CSS); `find()` gives `[name, url]` pairs and runs on the first tune (again after finding nothing). The real-map page passes `stationsNear(lat0, lon0, fetch)`: radio-browser.info (free, no key, CORS `*`, `all.api` = round-robin over its mirrors), the most-clicked stations within 200 km plus that country's top ones (country = nearest geo-tagged station, since few stations have coordinates), max 30. Only `https://` and non-HLS streams: the site is HTTPS, and `<audio>` can't play HLS. The test track uses the Romanian `STATIONS` presets. Nothing is cached or stored. Tested in `test/radio.test.js` (`npm test`).
- `touch.js` is the on-screen driving controls for both drive pages. `touchControls(extras)` (called from each page's `begin()`) keeps only steer ◀ ▶, Gas and Brake/Reverse on screen (held); the ••• toggle opens a panel with Handbrake (held) and the page's `[label, code]` extras (Lights, Camera, Radio…, tapped). Every button just dispatches the `KeyboardEvent` its key would (`ArrowLeft`, `ArrowUp`, `Space`, `KeyH`, …) on `window`, so the pages' own key handlers drive the car and there is no separate touch path. Hold buttons capture their pointer so a finger sliding off doesn't let go. The controls show when the primary pointer is coarse or after any touch, and hide on a real (trusted) key press. It makes its own elements and `<style>`; while the controls are shown `<html>` has the class `touch-ui`, which the real-map page uses to move its minimap to the top left and its street name clear of the buttons.
- `gamepad.js` is gamepad support for both drive pages: `gamepad()` → `{ poll(), crash(speed), feel(speed, braking, ride) }`. Each frame the page calls `poll()` (first connected pad, feature-detected, null without one; pure `padControls(gp)` → `{ steer, thr, brk, hb, keys }`) and passes it to `readKeys(keys, pad)`, which adds analogue `steer`, `thr`, `brk` (held keys override at full); `step()` uses them when present, so keyboard and touch are unchanged. Standard mapping: left stick steers, RT gas, LT brake, A handbrake; B, X, Y, LB/RB, Back and d-pad up press KeyB, KeyC, KeyR, Shift+KeyQ/KeyQ, KeyJ and KeyH (not Start: a pad can't close Settings again) by dispatching key events on `window`, like touch.js. Rumble (`vibrationActuator`, and `navigator.vibrate` on touch screens for crashes) on crashes, slides and rough ground. Tested in `test/gamepad.test.js`.
- Graphics quality (`quality.js`, pure, tested): `QUALITY` tiers Low/Medium/High set the pixel budget, MSAA (fixed when the renderer is made, so a change reloads), the shadow map size, the most traffic cars and pedestrians, and the rain drops. `pickQuality(stored, device)` uses the stored choice or `autoQuality` (desktops High, 4 cores or fewer Medium, phones Medium, small phones Low); `pixelRatio(q, dpr, w, h, scale)` keeps the frame inside the budget (at most 1.5, at least 0.6); `dynamicRes(apply)` is dynamic resolution: a slow 120-frame window (median over 20 ms) costs a tenth of the resolution (down to 0.7), five good ones (about 60 fps) win it back, and a step up that turns out too slow doubles that patience. Both pages pick the tier before making the renderer; the real-map page passes it to `createSky(renderer, scene, lat, { shadow, drops })`, traffic and people. Its camera's far plane sits just past the fog (`scene.fog.far + 30`).
- `perf-hud.js` is a performance readout for both drive pages (Settings → Performance stats, Shift+P or `?perf` in the URL; kept in `sedan-perf-v1`): fps, median and 95th-percentile frame time, the page's own work per frame, and `renderer.info` (draw calls, triangles, programs, geometries, textures), plus the tier and pixel ratio. `frame.lap(name)` times the parts of the real-map frame (drive, people, traffic, sync, sound, camera, hud, render). The Settings dialog also lists the controls (a `<details class="controls">` in the page).
- `car-merge.js`: `mergeStatic(car, keep)` bakes the driven car's still parts into one mesh per material and shadow setting (in the car's space), keeping the wheels, the steering wheel, transparent parts and the `keep` names (`tail_brake`) separate: about 300 fewer draw calls a frame. Both drive pages call it after `rigCar` and any lookups by name, so the named parts (`underbody` etc.) exist only before it; the viewer keeps the full car.
- Post-processing (`post-fx.js`, Medium and High): `postFx(renderer, scene, camera, q)` → `{ render, setSize, look, target }` or null (Low, or no half-float render targets). The scene renders into a linear half-float target, `UnrealBloomPass` (at half resolution) makes the lights glow (threshold 2.6 by day, 1.6 at night, so only emissive lamps pass, not sunlit or headlit surfaces), `OutputPass` tone-maps with the renderer's ACES and exposure, a small grade pass adds saturation, warm highlights and cool shadows and a vignette, and FXAA antialiases (4× MSAA on the half-float target cost ~5 ms of GPU on an M4, so there is no MSAA with post). `sky.set()` returns `post: { night, low, cover }` for `look()`. The three.js addon files are vendored from 0.184.0 (`examples/jsm/postprocessing/`, `shaders/`) and listed in all three import maps. Shader warm-up compiles against `fx.target`, because off-screen targets need programs without tone mapping.
- `car-probe.js`: `carProbe(renderer, scene, car, size)` → `update()`: a cube camera at the car renders the street one face a frame (the whole cube 10 times a second) into the env map of the car's shiny materials (metal, clearcoat, smooth), with the car hidden and the shadow map not redrawn; it waits two frames first so the shadow map exists. `size` is the tier's `probe` (128 High, 64 Medium, none on Low).
- Handling (`step()` in `drive-core.js`, 0.7.0): the tyres hold the car's path to `DRY` (15 m/s²) × grip sideways, and the steering lock stays just inside that (85%), so held keys never slide on dry ground. The handbrake leaves a third of the grip (the rear locks), hard braking a quarter less, throttle in a slide 0.75 of it (power-over keeps a drift going); with no steering input the car counter-steers and catches a slide. The body runs at most 0.65 rad ahead of its path. `collide(nx, nz, nh)` returns falsy (free), `'stop'` (refuse: people, the area's edge) or truthy (a solid the car may glance off: it tries paths turned 0.15, 0.3 and 0.5 rad, keeps the speed along the obstacle and turns towards it). `step()` returns `{ braking, reversing, blocked, impact }`; `drive-map.js` plays the crash (sound, shake, sparks, parcel damage) for a head-on block or the first frame of a glance (`scraping`), not again every frame it slides along. Roll and pitch are damped springs (`st.rw`, `st.pw`), so the body overshoots a little after braking and settles. `tyreSound` uses the same 15 m/s² limit, and `chaseCamera.orbit(st, t)` circles the car before the drive starts.
- `car-fx.js`: `carFx(scene, { particles, marks })` → `frame(dt, st, wheels, ride, braking, scraping)`, `spark(st, impact)`: tyre smoke (squeal on hard ground), skid marks (a ring of dark quads, the oldest fading; grey on snow, brown off the road), spray on wet roads, dirt or snow puffs off the road, and sparks from crashes and scraping. The tyres complain by `tyreSound`, so sight and sound agree. Budgets come from the tier (`particles`, `marks` in `quality.js`).
- First load (`area-fetch.js`, pure, tested; used by `map-data.js`): `fetchArea(lat, lon, { fetch, status, rested, rest, stagger, patience, vectorAfter })` → `{ first, full }`. The proxy and the Overpass servers race, at most two at a time (the next starts when one fails or none has answered for 8 s; a proxy 503 stops asking; 429/406 rest the host). After 6 s without a reply the simplified OpenFreeMap map is fetched alongside; `first` is the full map if it lands within 15 s, else the simplified one, and `full` keeps going. `loadArea()` saves the full map when it lands and returns `full` (resolves true once saved) with a simplified start; the page then shows a **Full map ready (U)** button (`#fullMap`), which reloads in place through `visitArea` with the pose (not during a delivery).
- Picker (`places.js`, pure, tested): `FEATURED` city centres as one-click chips, **Surprise me** (`surprise(r, last)`, never the last place), and recent places (`readRecent`, `addRecent`; stored on Drive).
- Hints (`hints.js`, pure, tested): `nextHint(state, shown, since)` picks the first hint whose moment has come (dark without headlights, stuck or off the road, idle without a job, able to afford an upgrade, then camera, weather, radio and settings after 90/150/210/270 s of driving), once each, at most one every 30 s, worded for keys or for the touch buttons. `drive-map.js` tracks the state in `hints()` and shows them as toasts. The start card lists four controls; Settings has the full list, the map stats and the Model viewer link, and the old key strip is gone.
- Street lamps that light: `buildWorld(…, { lampLights })` → `lampLight(x, z, dt)`, called from `updateCam`: `lampLights` point lights (3 High, 2 Medium, none on Low) hold the lamps nearest the car, fading out and in as they move, and stay in the scene at 0 by day so the light count never changes. With them the light pools under the lamps are fainter. Tree crowns are five lumpy blobs (`crownGeometry`) with a vertex shade that darkens the underside; the leaf material takes vertex colours.
- Performance: buildings, walls and trees are one mesh per 224 m tile (`TILE` in `world.js`, `splitByTile` in `geom.js`, one group per `mkMesh` call; the facade attribute travels as `B.f`), so the main and shadow passes skip tiles out of view. Before the loading panel goes, the page compiles every program for each lamp state (off, low beams, low and high beams, `renderer.compileAsync`), because three.js counts only visible lights: H and N then switch programs instead of compiling mid-drive. `models/vaz-2101.glb` has its textures at most 1024 px, opaque ones as JPEG.
- `toast.js` is the short messages on both drive pages: `toasts()` → `show(text, tone, key)`, dark pills at the top centre with a coloured edge (`good`, `bad`, `money`, `gold`: larger, 3.5 s), up to three at once; the same `key` replaces the one showing (T/E/N use 'time', V 'sound'). It makes its own elements and `<style>`.
- `result-card.js` (real-map page) is the card after a delivery: `resultCard(chime)` → `show(receipt, jobs, levelUp)`: the receipt line by line (`receiptText().head`, `.lines`), the pay counting up, `stars(receipt)` from `delivery.js` (0 ruined, 1 delivered, +1 on time with condition ≥ 0.7 and no fines, +1 within 0.8 of the time allowed at ≥ 0.95), progress to the next level and a gold level-up banner, with `driving-audio.js` `chime(kind, i)` sounds (pure `chimeNotes`, through the master gain so V mutes them). It hides after 5.5 s (not on keys, so driving off doesn't skip it), moves the toasts below it while up (`html.result-up`) and is compact under `html.touch-ui`.
- Chase camera (`chaseCamera` in `drive-core.js`): in mode 0 the camera sits in the car's frame at a yaw easing toward the travel direction (`st.h + 0.75·st.slip`), so its distance holds at speed (7.8 m at rest, FOV 58→72°) and slides show. `occluded(x, z, y)` is sampled along the boom at the sightline's height; it pulls in fast and eases out slowly. On the real map the occluders are buildings plus `posts` from `buildWorld()` (tree trunks, lamp posts, sign posts and boards) and the signal poles, in a `pointGrid` (`geom.js`). `laneSpawn` prefers a long straight lane ahead (`spawnSegments[i].run`): 40 m on the first start, 12 m after R.
- Delivery stops are marked by the ring and a 90 m additive beam (`delivery_beam`), amber for pickup, teal for drop-off, brighter at night (`update(x, z, speed, dt, night)`). Every new job is flashed with its distance and direction. `blobTex(inner, a)` in `world-kit.js` is the one soft contact-shadow texture (player car on both pages, traffic and parked cars, pedestrians); traffic and parked cars never take a paint close to the player's (`avoid(color)`, `parkedPaint` from `buildWorld()`, re-sent after a garage repaint).
- `three-d-stage.js` is a generic viewer web component (from the Claude Design starter, now owned here): renderer, studio lights, orbit, GLB/OBJ export.

- `area-travel.js` projects the crossing into a neighboring area, manages the boundary prompt and throttles travel attempts. The history entry carries the arrival pose, previous area for failed loads and cooldown fallback through a reload.
- `driving-audio.js` synthesizes engine and tuner sounds on both driving pages. Audio starts on a user gesture. Both pages pass `update(speed, forward, backward, ride)` the tyre state (`ride`: handbrake, `steer`, `slip`, rough ground, and on the real-map page the road's wetness, snow and grip); `tyreSound()` (pure, tested) turns it into a squeal (hard braking, handbrake, cornering past 70% of the grip limit, sliding; on hard ground only, less when wet), off-road/snow rumble and wet swish, played on three always-running looped-noise voices. `impact(speed, kind)` sounds a crash from `impactSound()` (pure, tested): a thump, a crunch, a metal ring for a `'car'` or `'post'`, breaking glass in a hard car hit and only a soft thud for a `'person'`, nothing under 1.2 m/s, and not again within 0.3 s unless much harder. `horn(on)` is the player's horn (B, and Horn on the touch panel), at least 0.3 s long. On the real map `blocked()` reports what the car hit (`'bld'`, a parked `'car'`, a `'traffic'` car, street furniture as `'post'`, a pedestrian as `'person'`), `SOLID` maps it to the crash sound, and a traffic car hit at over 2 m/s sounds a long horn back (`honkAt`, once per few seconds). On the real-map page it also voices the traffic: `trafficVoices(cars, ear, n)` (pure, tested) picks the four loudest cars within 80 m of the camera (`ear`: position, facing, the player's velocity, road wetness, the player's body) and gives each an engine note from `engineTone` with the Doppler shift of its speed relative to the listener and a small per-car offset, tyre hiss that grows with speed and on wet roads, a pan by side and a level by distance, a honk once it has been held up by the player for 3 s, and a screech when it brakes harder than 5.5 m/s² (`car.brake`, from `traffic.js`). `traffic(cars, ear)` plays them on a pool of four voices (oscillator + looped noise, through a stereo panner) under the master gain, so V mutes them too; a car keeps its voice while it stays among the loudest, and a voice only moves to a new car once it has gone quiet.
- Parcel deliveries on the real-map page use the directed traffic graph. `delivery.js` chooses local stops and handles handoffs. `delivery-hud.js` updates the prompt, road ring and minimap target. Jobs last for the current area. Once the parcel is collected the job is on the clock (`allowedTime(metres, drops)`: the straight-line round taken as 1.5 times longer by road at 9 m/s, plus 25 s and 15 s for each further drop-off, times the level's `ease` and the cargo's `time`), crashes damage it (`afterCrash`: nothing under 1.5 m/s, ruined at 75 km/h; `drive-map.js` passes every crash's speed to `delivery.crash`) running a red light costs `FINE` (`ranRed(graph.signals, …)` in `traffic.js` checks each physics step for a stop line crossed into a junction on red) and knocking into a pedestrian `KNOCK_FINE` (`knocked()`; the receipt names what the fines were for, `fined`). Jobs come in `JOB_LEVELS`, reached by deliveries made (`levelOf(wallet.jobs)`, so nothing new is stored): the first is easy (one parcel, legs up to 250 m, the clock ×1.3), and each after has more drop-offs (`drops`, up to 5), longer legs (`reach`), harder `CARGO` (`fragile`: crashes count double; `heavy`: the car's power ×0.72 and brakes ×0.85 while aboard, through `delivery.cargo` → `TUNE` each frame; `express`: the clock ×0.7) and a higher `pay` rate. `createDelivery(stops).start(x, z, level, kind)` plans the round: a pickup, then each drop-off reachable from the one before, 60 m on and 40 m clear of every other stop (planned up to six times for the whole group); `arrive()` says `'collected'`, `'dropped'` (more to go) or `'delivered'`, and `job` is `{ kind, cargo, parcels, delivered, level }`. `deliveryHud(…, paid, level)` plans jobs at `level()`, words its prompts by cargo and count, and `drive-map.js` flashes a level-up (`levelText`) and shows the level and how many more deliveries to the next in the wallet line. Delivering pays `deliveryPay()`: a base for the drop-offs and the distance (times the level's and cargo's rate), up to 40% more for arriving early, less for arriving late (down to a fifth a minute and a quarter late), less for the damage, minus the fines, never below zero. The HUD counts down while the parcel is aboard and shows the results card (`result-card.js`) on delivery; `drive-map.js` banks the pay in the wallet (below) and shows the cash under the status box. All of it pure and tested in `test/delivery.test.js`.
- Garage (real-map page, G, the Garage button or touch panel; driving pauses while it's open): `garage.js` (pure, tested) holds what delivery money buys, `UPGRADES` (engine tune, brakes, all-weather tyres, cargo padding, bought a level at a time) and `PAINTS`, with `price`, `buy(garage, wallet, item)` → `{ garage, wallet }` or null, and `carTuning(garage)` → `{ power, brake, grip(g), cushion, paint }`. `readWallet` / `readGarage` make stored data safe; the wallet `{ cash, earned, jobs }` starts from the old `sedan-map-earnings-v1` total when there is no wallet yet. `garage-panel.js` draws the dialog (`#garage`) and calls back with the item pressed; `drive-map.js` buys it, stores both, and fits it: `TUNE.power` and `TUNE.brake` (`step()` multiplies its brake deceleration by `tune.brake`), the weather's grip through `tuning.grip`, `delivery.crash(speed, tuning.cushion)` (`afterCrash` lets through only that share of the damage), and `repaint(CAR, hex)` from `drive-core.js` on the car's `paint` material (`buildCar()` and `loadVaz()` return it; the VAZ's own paint is a texture, which a colour replaces and Factory puts back). The upgrades are for the real-map page only; the test track keeps the stock car so lap times stay comparable.
- Traffic (real-map page): `traffic.js` (pure, Node-tested) → `laneGraph(roads, junctions, HALF)` splits the prepared roads (`road-layout.js`; `nodeKey` says which vertices are shared) where they meet into edges, one per direction, with a lane piece per lane cut back clear of each junction (by the meeting roads' widths and angle, `graph.armBack(road, i, direction)`, plus 3 m on a street with sidewalks so the crosswalk fits in front of the stop line); `createTraffic(graph, { rand, max, seen })` → `{ cars, step(dt, player, others), hit(x, z), clear(x, z, r), setLevel(level, x, z) }`. Each car plans its route about 120 m ahead (lane pieces joined by Bézier turns, rarely into dead ends), slows for bends, keeps its gap to whatever body is in its path (other cars, the player, and `others`: bodies with a radius `r`, the pedestrians in the road), and claims each junction before entering: no car in it may have a turn whose swept body touches its own (`compatible`), first come first served (a waiting car that can't go yet keeps its place from 4 to 20 s, so streams can't starve a side road and no circle of waiting cars lasts; a car held up by this one never blocks it), and there must be room beyond (no blocking the box). Junctions too close together to wait between are claimed together; a waiting car stops far enough back (`waitBack`) that no other turn or exit passes its body. Traffic lights: `laneGraph(…, signals)` takes the mapped `highway=traffic_signals` points (`buildWorld()` returns them as `signalPts`); a junction node with one within 30 m is controlled, and nodes joined by a short edge share a controller. With none mapped anywhere in the data (as on the vector fallback), lights go where two main roads (`MAIN`) cross at a four-way junction that isn't a roundabout. Every road into a controller gets a light in one of two phases by direction (the widest road's axis first) and a signal head at its kerb (`graph.signals`: `{ e, x, z, h, state, walk, junction }`, plus its stop line `cx, cz, ux, uz, half` for `ranRed`); `lightAt(signal, t)` cycles 18 s green, 3 s amber, 2 s all red per phase, then, where any road there has sidewalks, a walk phase with every light red (`ctrl.walk`: 6 s plus the widest crossing at 1.25 m/s; `walkLeft(ctrl, t)`, kept on each head as `walk`; `junction`: the controller's junction points, for matching crossings). Cars stop at red, and at amber when they can do so comfortably, without queueing for the junction meanwhile (a red light doesn't count towards being stuck); a car that claimed a junction on green gives the claim back if the light changes while it can still stop comfortably. `traffic-lights.js` draws the poles and heads (instanced) and the lamp that's on, glowing at night, and under each head a pedestrian signal facing across the road: red, green in the walk phase, flashing in its last 5 s. Cars live within 260 m of the player; `LEVELS` (Off/Light/Normal/Heavy) set the density. `seen(x, z)` (the camera frustum) keeps new cars from appearing on screen and lets cars stuck in a jam or at a dead end go once they're out of sight. `traffic-cars.js` draws them: one extruded body, glass, trim and lamps as `InstancedMesh`es, paint per car, brake lights, head and tail glows at night. `drive-map.js` steps it every frame (also before Start, not while paused; that also sets the lights), counts traffic cars as obstacles in `blocked()`, and clears cars from the spot you reset to. Tested in `test/traffic.test.js`.
- Pedestrians (real-map page): `pedestrians.js` (pure, Node-tested). `walkGraph(roads, paths, junctions, { armBack, roadAt, crossings })` → `{ nodes, edges }`, the walk network: both sidewalks of every `walk` road (`SIDEWALK` m outside the kerb, the middle of the 2.2 m sidewalk `world.js` lays), cut back at each junction to a crosswalk over every arm (`armBack` + `CROSSWALK`, in front of the stop line) and joined round every corner; past the mouth of a street without sidewalks the corner is a crossing over it. Where two streets meet end to end the sidewalks inside the bend stop where they meet. Any sidewalk piece that runs onto a carriageway (`roadAt`) is left out. Mapped footways, paths and pedestrian streets join in, split at shared nodes; a piece across a carriageway is a crossing, and the mapped `highway=crossing` points (`buildWorld()` returns them as `crossPts`) on streets with sidewalks are crossings kerb to kerb. A loose end within 3.5 m of another walkway is joined to it, not across a road. An edge's `cross` (`{ road, at, dir }`) marks a crossing. `createPedestrians(walks, { rand, max, radius, half, seen })` → `{ people, crossing, step(dt, player, cars, signals), setLevel, hit(x, z, h), bump(p, x, z), clear(x, z, r) }`: people (`{ x, z, h, v, r, phase, look, state }`) walk within 180 m of the player, keeping to their right, choosing a way at each node (crossings less often), and start out of sight. At a crossing they wait at the kerb (`state: 'kerb'`): at a junction with lights (every head whose `junction` is the crossing's, or for a crossing off a junction, within 25 m of it), only in the walk phase, every head red, with `walk` time left to get across and nothing on it, so never while any car there has green, and they give up after 120 s; elsewhere until no car (or the player) is coming within about 4 s, giving up after 45 s. On a crossing their `r` is 1.5 m, so traffic keeps out of the whole lane; `crossing` lists who traffic has to mind (on a crossing, stepped off their walkway, staggering), which `drive-map.js` passes as traffic's `others`. They step aside from the player's car coming at them and round it where it stands in their way; `bump()` (when the player hits one) sends them stumbling back (`'stagger'`). `PEOPLE` (Off/Few/Normal/Busy: up to 70/160/280 people, 90 on touch screens) set the density. `pedestrian-figures.js` draws them: body, head, hair, arms and legs as `InstancedMesh`es (group `pedestrians`, meshes `pedestrian_body`, …), clothes, skin and hair colours from `look`, limbs swinging with `phase` and speed. `drive-map.js` steps people before traffic every frame, counts them in `blocked()` (`'person'`: the car pulls up, a soft thud, `Watch out!` or the delivery fine) and clears them from the spot you reset to. Tested in `test/pedestrians.test.js`.

## Browser storage keys

- `sedan-area-cooldown-v1` (localStorage) — earliest time for another adjacent-area load, in epoch milliseconds.
- `sedan-driving-muted-v1` (sessionStorage) — whether engine and tuning sounds are muted in this tab.

- `sedan-map-last-place-v1` — last chosen place (real-map page)
- `sedan-drive-best-v2` — best lap time (Drive.html) (v2 from 0.7.0: the grip limits changed lap times)
- `sedan-lights-v1` — viewer light toggles (Sedan.html)
- `sedan-map-car-v1` — chosen car on the real-map page (`sedan` or `vaz`)
- `sedan-map-wallet-v1` — delivery money on the real-map page, `{ cash, earned, jobs }`: what's left to spend, all ever earned, deliveries made
- `sedan-map-garage-v1` — what the garage fitted, `{ levels: { engine, brakes, tyres, padding }, paints, paint }` (`readGarage` checks it)
- `sedan-map-earnings-v1` — before the garage, `{ total, jobs }`; no longer written, only read once to start the wallet
- `sedan-map-traffic-v1` — traffic level on the real-map page, an index into `LEVELS` in `traffic.js` (0 off … 3 heavy; normal when unset)
- `sedan-map-people-v1` — how many pedestrians on the real-map page, an index into `PEOPLE` in `pedestrians.js` (0 off … 3 busy; normal when unset)
- `sedan-map-recent-v1` — the last places driven on the real-map page, `[{ lat, lon, name }]`, newest first, at most 6 (`places.js`)
- `sedan-map-hints-v1` — the ids of the just-in-time hints already shown (`hints.js`)
- `sedan-quality-v1` — graphics quality for both drive pages: `"auto"` or an index into `QUALITY` in `quality.js` (0 Low … 2 High); set in the real-map settings (Graphics), which reload the area keeping the pose
- `sedan-perf-v1` — whether the performance stats show (`true`/`false`), both drive pages; Settings → Performance stats or Shift+P
- IndexedDB `sedan-map-cache` / store `osm` — cached Overpass responses, keyed `areaKey()` = `osm9:<lat>,<lon>:<HALF>` (4 decimals, snapped). Bump `CACHE_V` in `osm-query.js` whenever the query changes; entries with an older prefix are pruned after the next download.
- `sedan-geocode-cache-v1` — Nominatim results (last 60 searches / reverse lookups)
- `sedan-overpass-rest-v1` — Overpass servers to leave alone until a time (after HTTP 429/406)

## Conventions

- Code is written densely (many statements per line, short helper names like `V`, `B`, `add`). Match the surrounding style rather than reformatting whole files.
- Add any new library as an exact version under `vendor/<name>-<version>/` with its licence, not from a CDN. New textures go in `textures/`, CC0 only, with a row in `textures/README.md` (a test checks every `SURFACES` file is there and credited).
- `reference/` (git-ignored, local only) holds the photos the model was matched against (Logan front 3/4, front, interior, wheel, underbody) — look at them when working on the car's shape if they're present. They are third-party photos: never commit them; the repo is public.
